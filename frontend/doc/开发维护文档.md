# Artifex 前端开发维护文档

Artifex 是本地插画管理工具。用户把原图导入插画组，使用标签和生成提示词查找图片，用颜色组做自动分类或在白板上手动整理，再下载原图或导出 ZIP。前端负责浏览、交互与颜色组推断。Go 服务负责图像存储、缩略图、元数据、检索、模型推理和持久化。数据目录、迁移与服务运维见[后端开发维护文档](../../backend-go/doc/开发维护文档.md)。

## 从零启动

需要 Node.js、npm 和一个可运行的 Artifex Go 后端。发布流水线使用 Node.js 20，依赖版本由 [package-lock.json](../package-lock.json) 锁定。前端采用 React 19、React Router 7、Create React App（`react-scripts` 5），样式使用 Tailwind CSS 3、PostCSS 和少量独立 CSS，动画与图标分别使用 Framer Motion 和 Lucide。白板可选 PixiJS 8 渲染。

### 开发模式

1. 先启动后端，记下启动时显示的端口。默认监听 `127.0.0.1:8000`，端口被占用时会尝试后续端口。后端构建和独立测试库的准备步骤见[后端文档](../../backend-go/doc/开发维护文档.md)。
2. 在仓库根目录打开 PowerShell，执行下列命令。将 `8000` 换成后端实际端口。其他系统可用 `REACT_APP_API_BASE_URL=http://127.0.0.1:8000 npm start` 设置同一个变量。

   ```powershell
   cd frontend
   npm ci
   $env:REACT_APP_API_BASE_URL = 'http://127.0.0.1:8000'
   npm start
   ```

3. 打开 `http://localhost:3000`。当前后端跨域名单包含这个地址，`http://127.0.0.1:3000` 会被拒绝。项目没有 CRA `proxy` 配置，省略 API 地址时，请求会发往页面本身的端口。修改环境变量后重启开发服务器。变量也可放在 `frontend/.env.local`，使用 `REACT_APP_API_BASE_URL=...`。

首次联调可新建测试插画组，关闭自动打标或在缺少模型的提示中选择跳过，再导入一张图片。能看到缩略图、打开大图、刷新后仍看到插画，说明基本链路已通。

### 构建与同源联调

在仓库根目录执行以下 PowerShell 命令。`REACT_APP_API_BASE_URL` 在 CRA 构建时注入，打包时应留空（也检查 `.env.local` 等环境文件），使 API 与图片 URL 跟随 Go 服务的实际地址。

```powershell
cd frontend
Remove-Item Env:REACT_APP_API_BASE_URL -ErrorAction SilentlyContinue
npm ci
npm run build
cd ../backend-go
$env:CGO_ENABLED = '1'
go run . -no-ui -frontend ../frontend/build
```

`npm run build` 默认产出 `frontend/build/`。Go 的 `-frontend` 指向含 `index.html` 的目录。命令中的相对路径以 `backend-go` 为当前目录。Go 服务先注册 `/api`，再用静态文件和 `index.html` 处理 SPA 路由。启动后访问服务实际显示的地址，也可直接刷新 `/settings`、`/tags`、`/statistics`。`go run` 适合临时联调，默认配置和图库位于临时可执行文件所在目录。需要反复使用同一个开发库时，先从 `backend-go` 执行 `go build -o ./bin/artifex-dev.exe .`，再运行 `./bin/artifex-dev.exe -no-ui -frontend ../frontend/build`。入口和静态路由见 [main.go](../../backend-go/main.go) 与 [server.go](../../backend-go/internal/server/server.go)。

## 数据模型与接口边界

| 对象 | 常用字段和用法 |
| --- | --- |
| 插画组（`group`） | 有数字 `id`、`name`、`illustration_count` 与封面信息，是图片的实际归档容器。首页排序使用 `group_order` 存储数字 ID。 |
| 插画（`illustration`） | 有数字 `id`、`group_id`、`group_name`、`original_filename`、`file_size`、`width`、`height`、`created_at`、`tags`、`extended_data`、`file_url` 与 `thumbnail_url` 等字段。`tags` 是逗号分隔的字符串，自动分组与筛选会读 `extended_data['Positive Prompt']` / `['Negative Prompt']`。 |
| 颜色组方案（`set`）与颜色组（`pair`） | 一个插画组可有多个方案，`active_id` 选出当前方案。方案内的 `pairs` 决定显示顺序，`match_order` 决定自动推断优先级，`manual_assignments` 用插画 ID 的字符串映射到颜色组 ID。颜色组 ID 稳定，名称可重复且可改。 |
| 兜底分组（`other`） | 从推断结果派生的展示项。未归入任一颜色组时进入此项，白板对应圈外区。 |

[api/url.js](../src/api/url.js) 统一解析服务端相对 URL，支持可选 API 基地址。[api/library.js](../src/api/library.js) 处理需要保护馆藏身份的 `fetch`。页面首次获得 `X-Artifex-Library` 后，会一直把该身份附在后续请求里，直到页面重载。服务端以 HTTP `409` 拒绝旧馆藏身份的请求，避免切库后旧页面上传、下载或修改同 ID 的记录。普通图片标签和 ZIP 的原生下载链接没有自定义请求头。图片接口通过 `no-store` 避免切库时复用缓存，ZIP 下载票据由服务端绑定馆藏。

[api/index.js](../src/api/index.js) 的 JSON 包装将 `204` 解析为 `null`，非成功响应取 `{ detail }` 作为错误信息。表单上传使用 `FormData`。文件下载走原始 `Response` 或原生下载链接。查找具体请求名、参数和响应时，从前端包装定位到 [Go 路由表](../../backend-go/internal/server/server.go)。新增涉及馆藏的请求时沿用相同边界，带搜索或打标的写入需同步检查建议缓存失效。

| 场景 | 常用 API |
| --- | --- |
| 首页和插画组 | `GET/POST /api/groups`、`PUT/DELETE /api/groups/{groupId}`、`GET /api/groups/{groupId}/illustrations` |
| 导入和图片维护 | `POST /api/groups/{groupId}/illustrations/upload`、`PUT/DELETE /api/illustrations/{id}`、`POST /api/illustrations/tags`、`POST /api/illustrations/retag` |
| 预览和查找 | `GET /api/illustrations/{id}/file`、`/thumbnail?quality=...`、`/metadata`，以及 `GET /api/search`、`/api/tags`、`/api/prompts` |
| 馆藏统计 | `GET /api/statistics`、`GET /api/statistics/groups/{groupId}/storage`；颜色组详情还复用 `GET /api/group-config`、`GET /api/export/catalog?scope={groupId}` |
| 设置与方案 | `GET/PUT /api/settings`、`GET/PUT /api/group-config`、`POST /api/groups/{groupId}/color-operations` |
| 模型管理 | `/api/model/status`、`/api/model/download`、`/api/model/default`、`/api/models` 和自定义模型上传/删除子路由 |
| ZIP 导出 | `GET /api/export/catalog?scope=...`、`GET/PUT /api/export/draft/{scope}`、`POST /api/export/download`、`GET /api/export/download/{ticket}` |

## 状态存在哪里

| 范围 | 存储及入口 |
| --- | --- |
| 浏览器偏好 | [ThemeContext](../src/contexts/ThemeContext.jsx) 与 [LocaleContext](../src/contexts/LocaleContext.jsx) 分别用 `localStorage` 的 `gallery-theme`、`gallery-locale`。主题在 `<html>` 上切换 `dark`，语言默认英文。 |
| 项目设置 | [useProjectSettings](../src/hooks/useProjectSettings.js) 读写 `/api/settings`，由后端写入 `config.toml`。`useProjectPreference` 供白板渲染方式、圈外每行数量、普通下载命名等设置共享。 |
| 馆藏配置 | [useGroupSettings](../src/hooks/useGroupSettings.js) 通过 `/api/group-config` 读 SQLite 中的组顺序、每组的 `view` 和 `colors`。`useGroupViewSetting` 统一校验视图字段、默认值和提交方式，`useQuality`、`useCardSize`、`useOriginalRatio` 等进一步封装。 |
| ZIP 草稿 | 服务端按当前 SQLite 馆藏与 `scope` 保存。全馆使用 `all`，单组使用插画组数字 ID。 |
| 当前界面 | React 局部状态持有过滤文本、当前页、折叠项、选择、弹窗、灯箱位置、白板视图和暂存篮。全馆搜索传给 `useGroupConfig` / `useGroupViewSetting` 的组 ID 为空，因此颜色方案和视图设置只在该搜索实例内有效。 |

两个共享设置模块都通过 `useSyncExternalStore` 订阅模块内存状态。首次读取会合并同时发起的加载请求。写入先把待处理变更投影到界面，再串行提交。服务端返回最新已提交状态，前端在上面重放尚未完成的变更。请求失败时该变更退出队列并回滚相应投影，后续写入还能继续。设置页切换图库目录时先 `flushGroupSettings()`，更新 `database_dir` 成功后重载页面，让所有 Hook 与馆藏身份重新初始化。

## 日常业务流程

### 浏览、筛选与选择

[HomePage](../src/pages/HomePage.jsx) 获取组列表后应用 [useGroupOrder](../src/hooks/useGroupOrder.js) 的顺序。新出现的组排在已排序组之后。打开插画组时以组 ID 为 `key` 挂载 [GroupOverlay](../src/components/GroupOverlay.jsx)。`listAllIllustrations` 按 5000 条发起分段请求，组件获得全组数据后再在浏览器处理以下步骤。

首页拖动插画组时，网格层显示插入线、最终序号及相邻组名前后提示。预览与松手提交使用相同的坐标定位逻辑，覆盖卡间及跨行空隙，拖出、取消或失焦后清理提示。指示器样式在 [home-reorder.css](../src/pages/home-reorder.css) 中。

1. 按面积、文件大小、创建时间或服务端默认顺序排序。按标签和提示词做组内子串筛选。
2. 启用颜色分组时，在筛选结果上计算成员归属，按 `pairs` 的顺序分组，最后显示 `other`。
3. 先对每个组应用有限预览数量，再按分组后的视觉顺序分页。每个页面只重建与该页相交的组。无分组时直接切片。分页后的可见项按相同顺序提供给 Shift 范围选择和灯箱。

[ColorGroupGallery](../src/components/ColorGroupGallery.jsx) 支持 `single`、`double`、`mixed` 三种布局。`mixed` 根据实际响应式网格列数，用 [packColorGroups](../src/utils/colorGroupGallery.js) 填满行内余位，再把一个组切成连续区段，折叠组占一个位置。改变布局时应检查多段组的边缘、续接标识、折叠后焦点及实际阅读顺序。[ColorGroup](../src/components/ColorGroup.jsx) 同时用于搜索结果。分页与布局属于独立步骤，预览计数应在分组层保留。

全馆搜索由 [Layout](../src/components/Layout.jsx) 发起，`SearchOverlay` 请求 `/api/search` 后对当前结果支持二次筛选和临时颜色分组。当前只读取默认第一页（最多 100 条），服务端响应中的 `total` 可能更大。`useGalleryView` 统一处理单击开灯箱、Ctrl/Cmd 切换选择和 Shift 范围选择。组合测试时应使用当前可见顺序，而非数据库顺序。

### 上传、打标、预览与删除

- [GroupOverlay](../src/components/GroupOverlay.jsx) 汇合文件选择与拖入。白板和插画预览共用 [useIllustrationFileDrop](../src/hooks/useIllustrationFileDrop.js) 的文件拖放行为，依据 MIME 或扩展名筛选，并在不可接收时阻止浏览器打开文件。实际上传仍由服务端验证。
- 开启自动打标时先检查模型缓存。缺失则暂存本次文件，让用户下载模型或跳过自动打标。普通上传与跳过上传都由 [uploadBatches.js](../src/utils/uploadBatches.js) 按配置的 `upload_workers` 与 256 MiB 目标批次拆分，前端逐批发 multipart，Go 在批次内并行处理。单个超目标大小的文件仍单独发出，由服务端按请求限制校验。进度是按已完成批次计数，结果分为 `added`、`skipped`、`overwritten` 和 `failed`。成功新增或覆盖后重新拉取插画列表与首页组数据。
- [IllustrationCard](../src/components/IllustrationCard.jsx) 使用 `thumbnail_url` 和 `quality=low|normal|original`，原图档由后端直接返回原文件。组视图支持裁切方图和保持原始比例。白板卡片与悬浮预览使用独立的质量和尺寸常量，[IllustrationPreviewImage](../src/components/IllustrationPreviewImage.jsx) 会在加载失败时尝试低清图。[Lightbox](../src/components/Lightbox.jsx) 用 `file_url` 浏览原图，支持键盘导航、幻灯片、标签编辑、下载与按父组件提供的能力设置封面或删除。[useIllustrationMetadata](../src/hooks/useIllustrationMetadata.js) 仅在需要详情时加载完整元数据，快速换图时忽略迟到的响应。
- [TagPromptSuggest](../src/components/TagPromptSuggest.jsx) 复用标签与提示词 API。[tagPromptCache.js](../src/utils/tagPromptCache.js) 用 revision 共享在途请求和结果。成功上传、改标签、重新打标、删除等会刷新 revision，过期请求的结果不会回填缓存。标签批量添加/移除使用 `updated` 与 `missing` 更新界面并提示部分失败。
- 批量删除由 API 包装按去重后的 ID 逐条请求并返回 `deleted`、`failed`。更新列表、选择和手动分组时只处理已删除的 ID。分组清理由 `clear_assignments` 同步共享配置，搜索临时配置也单独清理。

### 颜色组规则与编辑

[grouping.js](../src/utils/grouping.js) 为图库、白板和导出共用。标签先按逗号拆分、去空格和转小写，再做完整标签匹配。提示词以正负提示词拼接后的文本做不区分大小写的子串匹配。规则由 `terms` 数组表达，每项有 `value`、`scope`、`operator`、`negated`、`open`、`close`。先处理单项取反，再按括号和 `AND` 优先于 `OR` 求值。方案按 `match_order` 取首个命中的颜色组，有效手动归组优先于推断，最后落到 `other`。空规则的颜色组可手动分配。

[GroupConfigModal](../src/components/GroupConfigModal.jsx) 记录所编辑方案的初始快照和本地草稿。保存时，[diffColorSet](../src/utils/colorConfig.js) 只根据初始快照发出确实编辑过的字段及相关操作。单组通过 `POST /api/groups/{id}/color-operations` 发送，例如 `update_pair`、`reorder_pairs`、`reorder_rules`、`assign`。Go 原子校验并提交批次，浏览器的 `applyColorOperations` 用于乐观重放和搜索中的临时方案。变更操作结构时，两端应同步。新组没有已存方案时使用空白 `Default` 草稿，首次有效保存时先发 `create_set` 的 `if_absent` 初始化操作。保存失败保留草稿与编辑目标，切换和新增方案前先保存当前编辑。白板的圈名修改走单字段 `update_pair`。

### 统计数字

`GET /api/statistics` 提供当前馆藏的插画组汇总和按天收录的稀疏序列。日历、每日折线与累计折线使用同一组日期数据。累计从保留插画的 `created_at` 推算，已删除、被覆盖的旧记录无法从现有库还原。日期以服务端库的本地日期为准。

存储区分 SQLite 文件、上传文件和模型文件。支持文件分配统计的平台显示分配字节，其他平台显示文件长度。插画组和颜色组分别展示插画数量和文件占用。插画组占用包含该组上传目录中的原图、两档缩略图和其他文件。展开插画组时加载该组的原图清单与单图占用，只把有关联的原图和缩略图计入颜色组明细。前端读取已保存的颜色方案，使用 [grouping.js](../src/utils/grouping.js) 与图库共用的归组算法计算各颜色组和未归组的明细。每个方案独立计算归属，同一插画可以出现在多个方案的统计中。

统计页的范围、年份、排序和颜色方案统一使用 [StatisticsSelect](../src/components/StatisticsSelect.jsx)。菜单通过 Portal 定位到页面上层，支持键盘选项导航、滚动、视口翻转及退出恢复焦点。颜色标记复用 `toHexColor` 从方案边框色取得实色，并为未归组保留独立的虚线标记。

## 白板的交互和渲染

[ColorGroupBoard](../src/components/ColorGroupBoard.jsx) 装配顶部控制、画布、悬浮预览、暂存篮和底部选择工具。父级 `GroupOverlay` 传入整个组的插画与当前颜色方案，接收持久化、上传、删除、下载及批量标签回调。

| 层 | 负责内容 |
| --- | --- |
| [colorBoardLayout.js](../src/utils/colorBoardLayout.js) | 由成员归属生成圆圈、卡片和圈外网格。布局以世界坐标描述，提供卡片命中、圆圈命中和视口筛选。圈外每行数量为项目设置 `board_free_row_limit`，可取 5–30，默认 10。 |
| [useColorBoardController](../src/components/color-board/useColorBoardController.js) | 两种渲染器共享的控制器，维护平移、缩放、指针捕获、框选、拖动目标、悬浮预览和暂存篮。高频变化通过 `requestAnimationFrame` 批处理并调用渲染器 `ref`，避免每次移动重渲整棵树。 |
| [DomBoardRenderer](../src/components/color-board/DomBoardRenderer.jsx) | 以 DOM 卡片和圆圈渲染，接受世界变换、拖动偏移及选框等命令。 |
| [WebGLBoardRenderer](../src/components/color-board/WebGLBoardRenderer.jsx)、[webglBoardScene](../src/components/color-board/webglBoardScene.js) | 懒加载 PixiJS 场景，维护可见卡片、选中/焦点/悬浮样式和缩略图纹理。按视口裁剪，纹理缓存预算为 256 MiB。标签、圈名和键盘辅助交互仍可由 DOM 提供。 |
| [BoardWorldUi](../src/components/color-board/BoardWorldUi.jsx)、[ColorBoardTray](../src/components/color-board/ColorBoardTray.jsx)、[ColorBoardSelectionDock](../src/components/ColorBoardSelectionDock.jsx) | 圈名与圈外列数控制、暂存篮、所选插画的批量下载/删除/标签工具。标签工具显示共同标签和部分图片拥有的标签，允许按持有者移除。 |

右键拖动平移，滚轮以鼠标位置为中心缩放，空白处左键拖动框选。画布缩放后，指针屏幕坐标须经视口原点和平移缩放逆变换再做命中检测。画布卡片拖到颜色圈会写入手动归属，拖到有效画布的圈外区域会清除手动归属，此后仍可能由规则自动分回某个颜色组。

拖到暂存篮只会在本次白板会话内隐藏对应画布卡片，原归属仍在。暂存篮选择和画布选择分开，选择工具取当前来源。将暂存项放到有效颜色圈并成功保存后才移出篮。无效放置或写入失败保留原项。「放回白板」恢复展示原归属。删除只清掉确认删除成功的项。离开白板会销毁篮及其选择状态。

[渲染器偏好解析](../src/utils/colorBoardRendererPreference.js) 中，`auto` 和 `dom` 目前都选 DOM，显式 `webgl` 才尝试 WebGL。加载/初始化失败或上下文丢失时退回 DOM。维护交互时优先改共享控制器，在两个渲染器分别验证拖动预览、选中层级、滚轮和键盘焦点。维护场景资源时确认切换渲染器、关闭白板和视口变化后会正确清理监听器、帧回调与纹理。

## 下载与 ZIP 导出

普通单图或所选图片下载由 [downloadIllustrations.js](../src/utils/downloadIllustrations.js) 逐张读取 `file_url`、创建 Blob URL、触发浏览器下载并释放 URL，保留每张成功与失败的结果。[useDownloadConfig](../src/hooks/useDownloadConfig.js) 的全局 `download_naming_format` 支持 `<date>`、`<group>`、`<Resolution>`、`<Model>` 等占位符，[NamingFormatInput](../src/components/NamingFormatInput.jsx) 负责输入。未填写或展开为空时回退原始文件名。

ZIP 导出从首页或插画组预览的「批量导出」入口进入 [BatchExportModal](../src/components/BatchExportModal.jsx)。该流程有自己的过滤条件、模板语法和持久化。

1. 并行读取所选范围的插画目录、上次草稿及馆藏分组配置。草稿按范围串行写入，输入防抖约 220 ms，关闭时把未提交的最后一份草稿加入队列。重开相同范围时等待该范围正在保存的草稿。
2. 支持按插画组、原始扩展名、导入日期区间过滤。选择为 `null` 表示全部，空数组表示全不选。导入日期取 `created_at` 的日期部分，区间包含首尾。颜色组名称取每个插画组的活动方案，并复用与图库一致的成员归属计算。导出日期/时间用浏览器本地时间。
3. 路径模板是字符串与 `{ key }` 令牌的数组。键以 `aggregation:` 或 `data:` 开头，标签可翻译，保存使用稳定键。例如 `[{"key":"aggregation:groupName"},"/",{"key":"data:original"}]` 是按插画组建目录并以原文件名保存。目录预览显示的每目录文件上限只控制预览，完整 ZIP 列表保持所有匹配项。
4. [batchExport.js](../src/utils/batchExport.js) 构造预览树和 `{ id, path }[]`。它验证相对路径、危险字符、保留名、段数和 UTF-8 长度，清理展开值，保留原扩展名，并为同目录内不区分大小写的冲突编号。前端命名段的预算是 200 字节，后端接受的段上限是 255 字节。两端均限制 24 段和 4096 字节的总路径。修改模板或路径规则时同时核对 [Go 导出校验](../../backend-go/internal/server/export.go)。
5. `POST /api/export/download` 提交清单并取得下载 URL。原生链接向服务端请求 ZIP，由服务端从当前馆藏读取原图并流式写出。票据短时有效且只用一次。「开始下载」提示表示已触发浏览器请求，可在浏览器下载列表确认完成。

模板编辑器依赖 DOM selection 和 `contentEditable` 来维护插入点，并在可用时用 CSS Highlight 标记错误字符。维护这里时检查纯文本粘贴、中文输入法组合输入、删除令牌、插入位置和键盘关闭浮层。样式与浮层定位入口分别为 [batch-export.css](../src/components/batch-export.css) 和 [ExportPopover](../src/components/ExportPopover.jsx)。

## 验证与排查

在 `frontend` 验证生产构建。

```powershell
npm run build
```

当前前端保留 CRA 的 Jest 脚本及 React Testing Library 依赖，提交 `1bf1b06` 已移除仓库中的前端测试文件。需要补回特定回归场景时，可用 `git ls-tree -r --name-only 82fe1df -- frontend/src` 查找上一版本中的用例。新用例可与源码并放，再用 `npm test -- --watchAll=false --runInBand` 执行。交接核对期间，移除前的 11 个套件、56 个测试均通过，生产构建成功。以实际构建产物联调 Go 时，已核对 `/settings` 深链接和静态文件加载、上传和缩略图、标签搜索、导出草稿和 ZIP 原图字节、切库后旧身份返回 `409`。

浏览器联调时，可在独立测试库用几张带标签或提示词、比例和扩展名各异的图片走一遍流程。

1. 创建、改名、排序插画组，刷新核对顺序。上传重名图片，检查不同冲突策略及只成功部分文件的反馈。
2. 给同一图片设置会命中的规则及不同的手动归组，检查手动优先和圈外回退。切换混排、预览数量、分页和灯箱，核对顺序。
3. 在 DOM 和 WebGL 下分别缩放、框选、拖入暂存篮和拖回圈内，检查关闭重开后仅已保存归组保留。用键盘检查可达控件和焦点。
4. 分别从首页和单组打开导出，验证草稿独立恢复。对比 ZIP 的文件数、路径与界面预览，尝试同名、无扩展名、多字节名称和跨日期范围。
5. 打开两个标签页，在一个标签页切换图库，确认另一个标签页的后续修改收到 `409`，重载后使用新库。
6. 从首页进入馆藏统计，刷新 `/statistics`。切换全馆和单组的日期视图，用键盘检查日历与折线；展开含多套颜色方案的插画组，核对手动归组、未归组和空颜色组，再用空库检查统计页的空状态。

常见问题优先看浏览器开发者工具的 Network 和 Go 服务日志。API 返回 HTML 或找不到接口时检查开发 API 基地址。跨域报错检查 `localhost:3000` 与实际后端端口。同源刷新页面失败时检查 `-frontend` 目录中是否含本次构建的 `index.html`。模型缺失可在设置页下载，也可在上传时跳过自动打标。

大组打开时，`listAllIllustrations` 会累积全组记录供前端筛选和分组。后端当前把列表 `offset` 封顶在 100000，前端按累计数推进。组数据超过 105000 条时后续请求可能重复取封顶处的记录。扩展大图库容量时需同步调整前后端翻页契约，并检验颜色组全量排序、分页和白板的内存及渲染开销。搜索的独立分页限制见上文。
